## 目标与范围

### 目标（0.2.0 要达成）

- **会话交互正确性**：停止、重试、撤回语义正确。
  - 点击停止后，UI 应在明确时限内进入已停止状态；若 dsh 支持中断当前生成，则应同时终止生成；若 dsh 不支持中断，应明确记录限制并提供降级行为。
  - 重试 = 撤回该消息 + 重发该消息，避免同一消息重复进入上下文。
  - 撤回应在当前会话内完成，不新建会话。

- **消息渲染正确性**：
  - 工具调用消息显示应与当前锁定 dsh 版本的官方类型契约一致。
  - 验收优先使用从参考会话导出的 fixture、日志、截图或脱敏样本，而非仅依赖本机实时会话。
  - 消除「仅思考 + 调工具」产生的空消息；思考与工具调用应合并到下一条有文本输出的消息中。

- **工具视图扩展**：
  - 新增文件管理器、终端、浏览器、Git 视图，作为 Code/AIDE 模式能力的延伸。
  - 本轮定位为 MVP，允许降级并标注能力边界。

- **环境与运行时管理**：
  - 支持 DSH WSL 配置与连接。
  - 支持 DSH 运行时下载、安装、管理。
  - 运行时下载必须明确下载源、版本锁定、校验方式、失败处理和回滚方式。

- **智能辅助提示**：
  - 提供 DeepSeek-V4-Pro 思维链降智检测。
  - 该检测为启发式提示，不阻断对话、不改变模型路由、不构成模型身份结论。

- **生态兼容**：
  - 兼容 DSH WebUI 热更新插件的 UI 展示层。
  - 在实现前需先 spike 官方插件 UI 挂载契约；若契约不可确认，允许降级或移出 0.2.0。

### 非目标（0.2.0 明确不做）

- 不存储/管理任何凭据；凭据零存储是硬限制，API Key 仍全部交给 dsh。
- 不修改 dsh 上游、不新增官方之外的协议层；`@deepseek-ai/*` 保持精确锁定。
- 不实现应用级花费/预算护栏、生产代码签名、Node/dsh 打入安装包、生产 CSP 收紧。
- V4-Pro 检测仅作提示：不阻断对话、不改变模型路由、不构成模型身份结论。
- 文件管理器/终端/浏览器/Git 为 MVP 视图，不追求 IDE 级完整能力。
- WSL 配置仅覆盖连接与基础配置，不做跨发行版全面管理；系统级写操作需确认。
- 插件兼容仅覆盖 UI 展示层，不实现插件沙箱、权限执行或插件运行时安全隔离。
- 若官方插件 UI 挂载契约无法确认，不强行实现插件 UI 加载。

## 验收标准

### 通用门禁（所有条目都必须满足）

- `npm run build` 通过（tsc 严格模式）。
- `cd src-tauri && cargo check` 通过。
- hooks 通过：
  - `pre-commit`：密钥/大文件检查。
  - `commit-msg`：Conventional Commits 检查。
- 硬限制不回归：
  - 凭据零存储。
  - 代理仅 loopback。
  - `@deepseek-ai/*` 精确锁定。
- 涉及协议链路、新增 Rust 命令、dsh 行为、工具渲染或会话状态的条目：
  - 必须提供可复查证据：类型、日志、时间戳、截图、fixture、会话导出或请求 payload。
  - 必须在 `docs/RISKS.md` 记录 dsh 版本与验证日期。
- 若某项验证无法完成，必须在交付说明中标记"未验证"或"证据不足"，不得声称完成。

### 运行时相关门禁（按需适用）

适用于涉及 dsh、代理、进程管理、会话流、工具执行、下载、安装、WSL 的条目。

- `npm run tauri dev` 运行验收：
  - 主窗口出现。
  - dsh 端口（默认 3080）被 node 进程监听。
  - 代理在 `127.0.0.1` 监听。
  - 优雅关闭后无残留进程。
- 若条目不触发上述运行时路径，可说明原因，并采用更窄而有效的验证方式。

### 条目级验收

#### 1. 文件管理器 / 终端 / 浏览器 / Git 视图

- 数据源与当前锁定 dsh 版本的官方类型契约一致。
- 已知类型契约沿用 `docs/RISKS.md`「2026-08-14：Code 模式数据契约」结论（原 DEV_PLAN 阶段 0 结论，DEV_PLAN.md 已归档删除）：
  - diff：`DiffResultView/FileDiff`
  - 终端：`TerminalCallView/TerminalResultView`
  - 文件：`ReadResultView`
  - 路径：`ToolEventView`
- 各视图可打开、可交互；无法完整实现的视图允许降级，但必须标注能力边界。
- 宽度 ≤1280 时按设计稿隐藏/折叠。
- 若某一子视图无法达到 MVP，可降级为只读视图、隐藏入口或移出 0.2.0，并记录原因。

#### 2. DSH WSL 配置与连接

- 检测 WSL 状态并显示，例如使用：
  - `wsl --status`
  - `wsl -l -v`
- 配置项可读写，并进行必要校验：
  - 路径是否存在。
  - 发行版是否存在。
- 无 WSL 环境时 UI 明确降级，不阻塞主流程。
- 非 Windows 或 WSL 不可用时，应显示不可用原因。
- 写操作遵循：
  - 最小权限。
  - 用户确认。
  - 失败可恢复。
  - 不擅自修改系统级配置。

#### 3. DSH 下载 / 安装 / 管理

- [事实] `DownloadsApi.sessionLog` 仅为会话日志 ZIP 下载，不是运行时下载；需自研下载管道。
- 明确运行时下载源、版本元数据来源和安装目标目录：
  - 首选下载源：npm registry（复用 `runtime/` 先例：`@deepseek-ai/dsh` 精确锁定版本）。
  - 备选：GitHub release（若上游提供可信发布物）。
- 版本精确锁定，禁止使用未锁定版本。
- 安装前必须完成完整性校验：
  - hash 校验为必须项（npm integrity 或 sha256）。
  - 签名校验视上游是否提供可信签名而定；若上游无签名，应记录风险并至少校验 sha256。
- 校验失败时禁止安装。
- 覆盖异常路径：
  - 下载失败。
  - 校验失败。
  - 磁盘空间不足。
  - 目标目录无权限。
  - 已存在旧版本或冲突版本。
- 已安装运行时可识别，版本可查。
- 支持回滚或恢复到上一可用版本；若无法回滚，必须明确说明原因和风险。
- 安装后通过 `DEVELOPMENT.md` 中的最小验收清单。
- 全流程不引入凭据存储，不暴露敏感信息。

#### 4. DeepSeek-V4-Pro 思维链降智检测

- 模型可识别性前置：需先 spike 实证 DeepSeek-V4-Pro 在当前锁定 dsh 版本的模型目录（`llm.models` / 会话元数据）中可识别（id 或 displayName 精确匹配）；未确认前视为假设，不作为既成事实。
- 仅在会话显示/请求模型可识别为 DeepSeek-V4-Pro 时启用检测。
- 正则规则可配置，配置位置明确。
- 默认规则应保守，避免高误报。
- 触发条件和解除条件明确。
- 提示必须为非阻断式警告：
  - 不阻断对话。
  - 不改变模型路由。
  - 不构成模型身份结论。
  - 不暗示确定性故障。
- 建议措辞示例：
  > 检测到当前思维链可能异常，存在被路由到低质量模型或生成质量下降的可能。该提示为启发式判断，不代表模型身份结论。
- 提供样本会话的误报/漏报评估记录。

#### 5. 停止按钮

- 模型思考中点击停止后，UI 应在明确时限内进入已停止状态。
  - 建议默认时限：2 秒；若后续实测证明需调整，应在 `docs/RISKS.md` 记录调整原因。
- 停止后无继续追加的流式内容。
- 停止后 UI 状态一致，可再次发送消息。
- 若 dsh 支持中断当前生成：
  - 提供日志、时间戳或协议事件证明生成已终止。
- 若 dsh 不支持中断当前生成：
  - 明确记录为已知限制。
  - 降级方案可为前端止流、断开当前连接、重连或清理 UI 状态。
  - 不得将"前端停止"包装成"后端已终止"。

#### 6. DSH WebUI 热更新插件兼容

- 阶段 0：spike 官方插件 UI 挂载契约，并输出结论。
  - 是否存在插件 UI 类型。
  - 插件 UI 如何注册、挂载、卸载。
  - 前端如何获知入口。
  - 失败和异常如何传播。
- 若契约可确认：
  - 支持加载插件新增 UI 视图并显示入口。
  - 插件卸载后入口清理。
  - 插件加载失败不阻塞主流程。
- 若契约不可确认或上游不支持：
  - 降级为只读展示、受限入口、文档说明。
  - 或移出 0.2.0，并记录后续迭代。

#### 8. 工具调用消息显示

- 使用参考会话导出的 fixture、日志、截图或脱敏样本作为验收基准；优先使用官方 session-export 导出的 `session.jsonl`。
- 对照当前锁定 dsh 版本，逐类工具渲染一致。
- 若无法导出参考会话：
  - 至少记录会话 ID、dsh 版本、验证日期和截图。
  - 同时在 `docs/RISKS.md` 标记证据可复现性不足。
- 修复后需更新 `docs/RISKS.md` 中"会话历史工具事件为通用映射渲染"的相关记录。

#### 9. 空消息合并

- 模型仅思考 + 调用工具时，不输出空消息。
- 思考与工具调用合并到下一条有文本输出的消息中。
- 使用参考会话导出的 fixture、日志或截图验证；优先使用官方 session-export 导出的 `session.jsonl`。
- 若参考会话无法导出，按条目 8 的降级证据要求处理。

#### 10. 重试语义

- 重试应等价于：
  1. 撤回该消息。
  2. 再发送一次该消息。
- 验收时通过以下至少一种方式证明消息未重复进入会话上下文：
  - 会话历史。
  - 会话日志。
  - 会话导出。
  - 请求 payload。
  - dsh 可观察会话状态。
- 若无法直接验证"模型上下文"本身：
  - 以 dsh 可观察会话状态为准。
  - 明确记录验证边界和剩余风险。
- 不得仅凭 UI 表现判断上下文未污染。

#### 11. 撤回语义

- 撤回应在当前会话内完成，不新建会话。
- 验收时通过以下证据判断：
  - 会话 ID 不变。
  - 会话历史连续。
  - retract/fork 日志或状态变化可查。
- 明确说明 retract 与 fork 的语义差异。
- 若现有 dsh 协议无法支持"当前会话内撤回"：
  - 记录协议限制。
  - 提出降级方案或移出 0.2.0。

  - 官方插件 UI 挂载契约 spike 结论。
- 条目 2 额外依赖：
  - Windows + WSL 环境。
  - 目标发行版可用。

### 风险

#### 高风险（需 spike / 实证）

- **插件 UI 挂载机制未知**
  - 当前 pinned 包未提供明确 plugin-UI 契约，仅在 gateway/Cordis 侧有相关线索。
  - 必须先 spike。
  - 若上游不支持或契约不稳定，MVP 降级为只读展示、受限入口、文档说明或移出。

- **DSH 运行时下载/安装**
  - [事实] `DownloadsApi.sessionLog` 仅用于会话日志 ZIP 下载，不是运行时下载。
  - 需自研下载管道。
  - 首选下载源为 npm registry（复用 `runtime/` 先例），但仍需验证版本元数据与校验材料；备选 GitHub release。
  - 风险包括下载源变化、版本漂移、npm 分发不一致、校验失败、安装失败和回滚失败。
  - 若下载源或校验方式无法确认，应拆分或移出 0.2.0。

- **停止语义**
  - dsh 是否支持中断当前生成需实证。
  - 当前停止可能仅为前端双态。
  - 若不支持真正中断，应降级为前端止流、断开重连或其他可控方案，并明确记录限制。

- **工具视图范围较大**
  - 文件管理器、终端、浏览器、Git 是四个大功能。
  - 必须分阶段实施。
  - 无法全部达到 MVP 时，优先保证文件管理器和终端；浏览器/Git 可降级为只读、隐藏入口或移出。

#### 中风险

- **V4-Pro CoT 正则检测为启发式**
  - 误报/漏报不可避免。
  - 不构成模型身份结论。
  - 措辞必须保守。
  - 需要样本评估，并允许用户关闭或调整规则。
  - 模型可识别性（V4-Pro 出现在 `llm.models` / 会话元数据）需先 spike 实证，未确认前按假设处理。

- **WSL 配置涉及系统级权限**
  - 只读检测优先。
  - 写操作必须最小权限、用户确认、失败可恢复。
  - 不做跨发行版全面管理。

- **重试/撤回语义依赖 dsh 会话协议**
  - retract/fork 已有实现，但「撤回 + 重发」是否真正避免上下文污染需要用会话日志、导出记录或请求 payload 验证。
  - 若无法直接验证模型上下文，必须记录验证边界。

- **工具调用渲染与空消息合并依赖官方类型契约**
  - dsh 类型契约可能频繁变化。
  - 每次相关改动都需记录 RISKS。
  - 验收以当前锁定版本为准。

- **范围扩张**
  - 条目 1、2、3、6 均可能扩大范围。
  - 必须明确写集边界。
  - 不允许顺手修改无关模块、全局配置、凭据处理、生产配置或协议层。

#### 低风险 / 已记录

- 会话历史工具事件当前为通用映射渲染，已在 `docs/RISKS.md` 记录；条目 8 修复后需更新。
- CSP `'unsafe-inline'` 生产收紧为已有后续条目，不属于本轮范围。

## 裁剪与退出条件

出现以下情况时，允许将对应条目降级、拆分或移出 0.2.0：

- **条目 6：插件 UI 契约无法确认**
  - spike 无法确认官方插件 UI 挂载契约。
  - 处理方式：降级为只读展示、受限入口、文档说明，或移出 0.2.0。

- **条目 3：下载源或校验不可确认**
  - 无法确认可信下载源、版本元数据、hash/签名校验方式。
  - 处理方式：拆分为"下载调研 / 安装管理"，未完成部分移出 0.2.0。

- **条目 5：dsh 不支持生成中断**
  - 无法通过日志或协议事件证明后端生成可终止。
  - 处理方式：验收降级为前端止流、UI 状态一致和可再次发送；明确记录后端未终止风险。

- **条目 1：工具视图无法全部达到 MVP**
  - 四个工具视图中部分能力不足或类型契约不稳定。
  - 处理方式：优先保留文件管理器和终端；浏览器/Git 可只读、隐藏入口或移出。

- **条目 2：WSL 写操作风险不可控**
  - 写操作无法做到最小权限、用户确认或失败恢复。
  - 处理方式：仅保留只读检测和手动配置指引，写操作移出。

- **条目 10/11：dsh 会话语义不支持**
  - 无法通过会话日志、导出或请求 payload 验证重试/撤回语义。
  - 处理方式：记录协议限制，降级为 UI 层语义或移出。

所有裁剪、降级或移出决定都应更新本文件、`docs/RISKS.md`，并在提交信息中说明原因。
